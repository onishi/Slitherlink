# スリザーリンク

ブラウザで遊べるスリザーリンク（ループ・ザ・ループ）です。
出題される問題は **すべて、当てずっぽう無しで論理だけで解けること** を確認してから配信されます。

- フレームワーク・ビルド・依存パッケージなし（バニラ ES Modules + SVG）
- 作問は Web Worker で行うので、考えている間も UI が固まりません
- スマホのタップ、マウス、キーボードのどれでも遊べます

## 遊び方

点と点をつなぐ線を引き、**ひとつながりの輪をひとつだけ** 作ります。
マスの数字は、そのマスの周囲 4 辺のうち何本に線が引かれるかを表します。
数字のないマスに制限はありません。輪は枝分かれ・交差・途切れができません。

| 操作 | 効果 |
| --- | --- |
| 辺をクリック／タップ | 線 → × → 空白 と切り替え |
| 触れたまま指をずらす | 何も起きない（変わるのは最初に触れた 1 辺だけ） |
| 右クリック／Ctrl+クリック | × を直接付け外し |
| 矢印キー | カーソル移動 |
| スペース / Enter | 線を引く・消す |
| X | × を付ける・外す |
| Ctrl+Z / Ctrl+Shift+Z | もどす / すすむ |
| H | ヒント |
| Escape | ヒントや定石サイドバーをとじる |

ヒントは「どこが決まるか」に加えて **なぜそう決まるか** を説明します。
盤面の実際の数字や本数を使った文章（例:「上から 3 番目・左から 2 番目のマスの 3 は、
まわりにもう線が 3 本。必要な数がそろっているので、残りの辺にはもう引けません」）と、
根拠になっているマス・交点・辺のハイライトが出ます。
そのまま置くことも、自分で考えることも選べます。

ヒントには必ず **いまの盤面から一歩ずつたどれる証明** が付いています。

- 盤面を見ただけで基本ルールが 1 つ当てはまる手は、そのルールと根拠の印を示します
- そうでない手は背理法で示します。「ここを線と仮定する → 3行2列のマスの 3 は × が 1 本
  → 残りは線 → … → 矛盾: 4行3列の点が行き止まりになる」のように、**矛盾までの手順を
  一手ずつ** 並べます（「根拠を一手ずつたどる」）。仮定の中でさらに仮定が要るときは、
  その中身も字下げして全部書きます
- 仮定したときに決まっていく印は、盤面に点線と緑の × で重ねて表示します
- 手順の各行は、数字の本数・交点の線は 0 本か 2 本・輪はひとつだけ、のどれか 1 つだけで
  決まります。各行には「何が分かっていたからそう決まったか」（前提の辺）が付いていて、
  `checkProof` がそれだけを見て **一から検算** します。検算に通らない証明は出しません
- 候補が複数あるときは、手順のいちばん短いものを選びます

## 画面の配置

使う頻度で置き場所を分けています。

| 頻度 | 置き場所 | 中身 |
| --- | --- | --- |
| 解いているあいだずっと | 盤面のすぐ下の 1 列 | もどす・すすむ・線／バツの切り替え・チェック・ヒント |
| 1 問に 1 回 | 盤面の上 | 新しい問題（大きさ・むずかしさは横の「7 × 7 ・ ふつう ▾」から） |
| ときどき | 右上 | 定石一覧・遊び方 |
| めったに使わない | 右上の「⋯」 | 表示の設定・テーマ・問題コード（共有と読み込み）・書き込みをぜんぶ消す |

ヒントの説明は、ヒントを押したボタンのすぐ下に開きます。

## 定石一覧

「こういう配置になったら、こういう理由でここが確定する」を図つきで並べた
一覧です。ゲーム画面のヘッダーの「定石」からサイドバーで開けます
（`patterns.html` は同じ内容の単独ページ）。
43 個の定石を **出番の多さで 3 段**（よく使う＝1 問あたり 5 本以上／ときどき使う＝1 本以上／
たまに使う）に分け、段の中も出番の多い順に並べています。ゲーム中のサイドバーでは「たまに使う」と
「図の読み方」は畳んであります。カードには分類と出番の多さ
（1 問を解くあいだにその定石で決められる辺の本数の実測平均）を出します。

出番は `node tools/pattern-stats.js` が実測して `src/core/pattern-stats.js` に書き出します。
7×7・10×10 をやさしい・ふつう・むずかしいで 4 問ずつ、ヒントどおりに最後まで解き、
途中の盤面ごとにその定石で埋められる辺を集めて、1 問ごとに重複なしで数えます
（盤面ごとの「使えたかどうか」で数えると、すぐ使われてしまう易しい定石ほど少なく見えるため）。
seed は固定なので、何度走らせても同じ値になります。定石を足したら走らせ直してください
（実測値の無い定石があるとテストが落ちます）。

ゲーム画面のサイドバーには **「いま使える定石だけ表示」** の切り替えがあり、オンにすると
いまの盤面に当てはまる場所がある定石だけが残ります（盤面が変わるたびに絞り直し、
状態は次に開いたときも保たれます）。

うち 5 つは型の照合ではなく、**ルールそのものを盤面全体に適用**します
（`match` フィールド）。

| 定石 | ルール |
| --- | --- |
| 交点に集まる線は 0 本か 2 本 | 枝分かれ・交差・行き止まりの禁止 |
| 数字の本数がそろったら、残りは × | 数字はまわりの線の本数（どの数字・どの向きでも） |
| 残りを全部使わないと届かないなら、残りは線 | 同上（1 の 3 辺が ×、2 の 2 辺が ×、3 の 1 辺が × など） |
| 閉じ込められた場所には入れない | 線は輪の一部（どこかで戻ってくる） |
| 小さな輪を閉じてはいけない | 輪はひとつだけ |

「交点の線は 0 本か 2 本」は、型では拾えない向き（まっすぐ進む形、一直線に
並ぶ 2 本、盤の角や縁の点）も含めて処理します。「閉じ込められた場所」は、
× を取り除いた図で橋になっている辺（通ると戻ってこられない辺）を × にします。
交点ごとの数え上げでは届かない形が決まります。

定石の候補は、参考文献が挙げる配置を出発点に、盤で総当たりして
「何が確定するか」を機械的に洗い出したものです。
採用するかどうかは、**いまの一覧を繰り返し適用しても導けない結論を
持つかどうか**で決めています（既存の定石の組み合わせで済むものは載せません）。となり合う 2 数・斜めの 2 数・3 つ並び・1 マス空けた 2 数・
角と縁の数字・数字と印の組み合わせを一通り調べ、確定するものだけを採用しました。
逆に、1 と 1 / 1 と 2 / 2 と 2 / 2 と 3 のとなり合わせ、縁の 1・2・3 などは
**それだけでは何も確定しない**ことも確かめています。

### ヒントの証明から見つけた定石

背理法のヒントには、矛盾までに使った数字と印がすべて記録されています（前提）。
`node tools/mine-patterns.js` は、問題をヒントどおりに解きながら次の手を拾います。

1. 背理法のヒントで、いまの定石をくり返し当てはめても届かない辺
2. 証明が「輪はひとつだけ」を使っていない（盤面全体に依存しない）もの
3. 盤の縁の点を使っていない（どこにでも置ける）もの

その証明が使った数字と印だけを取り出し、回転・反転をそろえて数えると、24 問のヒント
3884 手のうち、定石では届かない内側の形は 116 手・42 種類ありました。複数の問題に
くり返し出てくる形を、その形だけを置いた盤でも定石では届かないことを確かめてから、
6 個を足しています（`origin: 'hint'`）。

| 定石 | 出てきた問題 |
| --- | --- |
| 片側が × の 2 の角に、外から線が来た | 12 問 |
| 片側が × の 2 の角が、× でふさがれた | 5 問 |
| 2 辺が × の 1 の角に、外から線が来た | 3 問 |
| 3 の 2 辺に 1 がとなり合う | 6 問 |
| 片側が × の 2 と、斜めの 3 | 4 問 |
| 2 辺が × の 1 と、斜めの 3 | 3 問 |

足したあとは、定石で届かない内側の形が 56 手・32 種類に減り、残りはどれも 2 問以下にしか
出てこないため見送りました。どれも他の定石と同じ検証（総当たり・余白つきの盤・
8 方向）を通り、さらに **ほかの定石をどう組み合わせても結論に届かない** ことをテストで
確かめています。

### 「輪はひとつだけ」に頼る定石

となり合う 3 と 3 のまん中の辺は、閉路禁止（輪はひとつだけ）があって初めて
線に決まります。2 マスをまとめて囲む長方形の輪でも 3 と 3 自体は成立するため、
その長方形が答えそのものになりうる盤面（ほかの数字がすべて 0 か、数字が無い）
では決まりません。照合ではこの条件を毎回判定しています
（`smallLoop` / `loopConclude`）。

ほかに同じ理屈が効く定石がないかを機械的に洗い出しました。

- 当時収録していた 34 個すべてについて、遠くに数字を 1 つ足した盤面と足さない盤面で
  確定する辺を比べた結果、**追加で確定したのは「3 と 3 がとなり合う」だけ**
- 「小さな輪がその数字をぴったり満たしてしまう」形（1〜6 マスの 12 種類）を
  総当たりした結果、閉路禁止で何かが増えるのは横 2 マス（3-3）と
  T 字 4 マス（3-1-3-3）のみ。後者は他の定石だけで同じ結論に届き、
  40 問中 0 回しか現れないため収録していない

定石ごとに「当てはめる」ボタンがあり、押すと **いまの盤面からその定石が
使える場所をすべて探して、決まる印を引きます**。ボタンの数字は当てはまる
場所の数で、盤面が変わるたびに数え直します（全定石を数えても 1ms 未満）。

当てはめは `src/core/pattern-match.js` が行います。定石は 1 つの向きだけ
書いておき、回転・反転の 8 通りに変換してから盤面を走査します。
角の定石は盤の角に合わせたときだけ使います。

定義の `rows` / `cols` は図を見やすくするための枠で、まわりの余白マスは
推論に使っていません。そのため照合では枠ではなく、**実際に参照する数字と辺**
だけが盤に収まるかを見ます（枠ごと収まることを求めると、盤の端にある 0 などを
取りこぼします）。

載せている内容は `src/core/patterns.js` に宣言的に書かれていて、
`tests/patterns.test.js` と `tests/pattern-match.test.js` が毎回検証しています。

- 小さな盤では **総当たりで全解を調べ、反例が 1 つも無いこと** を確認
- まわりに余白を足した大きな盤では、論理ソルバで **否定すると矛盾すること** を確認
- 前提そのものに解があること（空虚な真になっていないこと）も確認
- 回転・反転した 8 通りそれぞれについても同じ確認
- 盤の端にかかる置き方も含め、置ける位置すべてで結論が確定することを総当たりで確認
- 結論の一部が盤からはみ出す置き方でも、盤に残る結論が確定することを総当たりで確認
- 生成した問題に全定石を当てはめ続け、**埋めた辺が 1 本も正解と食い違わないこと**
  を確認（実測: 30 問・1817 本を埋めて食い違い 0）
- どの定石も、その形を盤に作れば必ず見つけられることを確認

この検証の過程で、よく「隣り合う 3 と 3 のあいだの辺は線になる」と
説明される定石が成り立たないことが分かりました（2 マスをまとめて囲む
長方形の輪が反例になります）。ページではその点も注記しています。

## 起動

```sh
npm start          # http://localhost:8080/ で開く
```

`file://` で直接開くと Web Worker と ES Modules が動かないため、必ず HTTP で配信してください。

## 公開

`npm run build:site` が、配信に必要な `index.html` と `src/` だけを `_site/` に集めます。
テストや開発用ツールは含まれません。

### Cloudflare（既定）

`.github/workflows/cloudflare.yml` が、既定ブランチへの push でテストを走らせたあと
`wrangler` で Cloudflare Workers（静的アセット配信）へデプロイします。
設定は `wrangler.jsonc` の 1 ファイルだけです。

必要なのはリポジトリのシークレット 2 つです。
**Settings → Secrets and variables → Actions** に登録してください。

| 名前 | 中身 |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Workers のデプロイ権限を持つ API トークン |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare ダッシュボードのアカウント ID |

API トークンは Cloudflare の **My Profile → API Tokens → Create Token** から、
テンプレート **Edit Cloudflare Workers** で作れます。
公開先は `https://slitherlink.<サブドメイン>.workers.dev` です。

シークレットが未設定のあいだは、デプロイ手順だけを黙ってスキップします（CI は緑のまま）。

ダッシュボードから Git 連携で Cloudflare Pages に繋ぐ方法でも動きます。
その場合のビルド設定は次のとおりです。

- ビルドコマンド: `npm run build:site`
- ビルド出力ディレクトリ: `_site`

### GitHub Pages（手動）

`.github/workflows/pages.yml` を Actions タブから手動実行すると GitHub Pages へ配信します。
初回だけ **Settings → Pages → Source** を **GitHub Actions** にしてください
（Pages サイトの作成は Actions の `GITHUB_TOKEN` の権限では行えないため、ここは手作業になります）。
公開先は `https://<ユーザー名>.github.io/<リポジトリ名>/` です。

どちらの配信先でもすべて相対パスなので、サブディレクトリ配信のままで動きます。

## テスト

```sh
npm test           # 単体テスト（約 1 秒）
npm run verify     # 実際に作問して論理的可解性と解の一意性を検査
```

## 「必ず論理的に解ける」の担保

作問は次の手順です。

1. 内側マスの集合をランダムに育て、その境界がつねに **単一の閉ループ** になる変更だけを採用する
2. できた輪からすべてのマスの数字を求める
3. 数字をランダムな順に 1 つずつ消し、消すたびに **論理ソルバだけで最後まで解けるか** を確かめる。
   解けなくなる数字は元に戻す

ソルバが使う推論は次のものだけで、探索による総当たりは含みません。

| ルール | 内容 |
| --- | --- |
| R1 数字の充足 | 線が数字に達したら残りは ×、残り全部を使わないと届かないなら残りは線 |
| R2 交点の次数 | 各交点の線は 0 本か 2 本。端は必ずもう 1 本つながる |
| R3 閉路の禁止 | 全体が完成しないのに輪を閉じてしまう辺は × |
| R4 背理法 | ある辺を仮定すると R1〜R3 だけで矛盾する → 反対の値に確定 |

難易度は R4 をどこまで使うかで決まります。

| 難易度 | 使う推論 | 数字の残り |
| --- | --- | --- |
| やさしい | R1〜R3 のみ（背理法なし） | 約 45% |
| ふつう | ＋ 背理法 1 手 | 約 37% |
| むずかしい | ＋ 背理法 2 手 | 約 32% |

盤面の総当たりソルバ（`countSolutions`）は検証専用で、出題には使いません。
テストでは、生成した問題が「宣言した難易度の推論だけで解ける」「解が一意」「正解が単一ループ」であることを毎回確かめています。

### 証明だけで解き切れるかの確認

ソルバの「解けた」は、背理法の候補をどの順で試すかに左右されます。実際、空の盤面からは
解けるのに、途中まで進めた盤面からはソルバが先へ進めず、ヒントが「もう決まる場所はない」と
止まってしまう問題がありました。

そこで作問の最後に、ソルバとは別の方法でもう一度確かめます（`solveWithProofs`）。

1. 空の盤面から、**検算に通る証明が付いた手だけ** を置いていく
2. 証明は、盤面だけで決まる手 → 仮定 1 つで矛盾 → 仮定を重ねて矛盾、の浅い順に探す
   （仮定の深さは難易度の上限まで。やさしいは仮定なし）
3. 正解まで届かなければ、その問題は捨てて作り直す

ヒントはこれと同じ証明探しを使うので、配信される問題は **どこまで進めても、正しく置いている
かぎりヒントが根拠つきで次の一手を示せる** ことになります。正しい値を否定する証明は作れない
ので、証明だけで全部の辺が決まれば解は自動的に一意です。

問題コードの読み込みも同じ確認を通ったものだけを受け付けます。
`npm run verify` は正解を使わずに（両方の値を仮定して）この確認も行います。

```

src/core/grid.js       盤面のジオメトリ（辺・頂点・マスの対応）
src/core/solver.js     論理ソルバ（R1〜R4）と検証用の総当たりソルバ
src/core/generator.js  ループ生成と数字の削り込み
src/core/game.js       進行状況の判定・自動 ×・ヒント（証明を言葉にする）
src/core/proof.js      ヒントの証明づくり・検算・証明だけで解き切れるかの確認
src/core/puzzle.js     問題コードの読み書き
src/core/patterns.js   定石の定義（テストで検証される）
src/core/pattern-stats.js 定石の出番の実測値（tools/pattern-stats.js が書き出す）
src/core/pattern-match.js 定石を盤面に当てはめる（回転・反転の照合）
src/ui/                画面（盤面描画・入力・保存）
src/worker/            作問ワーカー
tools/                 開発用サーバ・検証スクリプト・公開用ビルド・定石の洗い出しと出番の実測
wrangler.jsonc         Cloudflare への配信設定
tests/                 単体テスト
```

## 問題コード

`7x7:n:23123a0d1d2311a1e1a1e110a20e1a0` のような文字列で 1 問を表します。
`<縦>x<横>:<難易度>:<本体>` で、本体は数字をそのまま、空白マスの連続を `a`（1 マス）〜`z`（26 マス）で表したものです。
右上の「⋯」（設定とその他）の「問題コード」から読み込み・共有ができ、`?p=<コード>` を付けた URL でも直接開けます。
