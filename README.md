# Grid Loop

ブラウザで遊べる、点と点を線でつないでひとつながりの輪を作るパズル「Grid Loop」です。
出題される問題は **すべて、当てずっぽう無しで論理だけで解けること** を確認してから配信されます。

- フレームワーク・ビルド・依存パッケージなし（バニラ ES Modules + SVG）
- ボタンのアイコンは Google Fonts の [Material Symbols](https://fonts.google.com/icons)（Rounded）を読み込んで使います。
  読み込めないときもボタンの文字とラベルはそのまま使え、アイコンの場所は 1 文字分の空きになります
- 作問は Web Worker で行うので、考えている間も UI が固まりません
- スマホのタップ、マウス、キーボードのどれでも遊べます。大きな盤はピンチや ＋ − で拡大できます

## 遊び方

点と点をつなぐ線を引き、**ひとつながりの輪をひとつだけ** 作ります。
マスの数字は、そのマスの周囲 4 辺のうち何本に線が引かれるかを表します。
数字のないマスに制限はありません。輪は枝分かれ・交差・途切れができません。

| 操作 | 効果 |
| --- | --- |
| 辺をクリック／タップ | 線 → × → 空白 と切り替え |
| 辺をなぞる | 点から点へ通った辺に線を引く（モードによらず）。続けていくつもの辺を引ける。線の上からなぞり始めると、なぞった線を消す |
| 長押し（指・ペン） | その辺に × を付ける（× なら消す） |
| 右ボタンでドラッグ | なぞった辺に × を付ける（× の上から始めると消す） |
| 2 本指のピンチ・盤面右上の ＋ − | 拡大・縮小（10 × 10 以上の盤。5 マスぶんが画面いっぱいになるまで）。拡大中は 2 本指で盤面を動かす |
| Ctrl + ホイール／ホイール | PC で拡大・縮小／拡大中の移動 |
| 右クリック／Ctrl+クリック | × を直接付け外し |
| ⌘ を押しながらクリック（Mac） | 押しているあいだだけ線と × のモードを入れ替える（マウスの形が付く印になる） |
| 矢印キー | 辺を選ぶ（盤面をクリックしていなくても動きます） |
| スペース / Enter | 選んだ辺に線を引く・消す |
| X | 選んだ辺に × を付ける・外す |
| M | クリックで付く印（線／×）を切り替える |
| Ctrl+Z / Ctrl+Shift+Z（Ctrl+Y）| もどす / すすむ（Mac は ⌘） |
| H | ヒントを出す・もう一度で消す |
| P | いま使える定石のカード・もう一度でとじる |
| ? | キーボード操作の一覧を出す・とじる |
| Escape | 手前に開いているもの（一覧・ヒント・定石・メニュー）をとじる／集中モードをやめる |
| 上の ⛶（集中モード） | 盤面だけを画面いっぱいに出す。残るのは拡大・縮小とやめるボタンだけ（使えるならブラウザも全画面に） |

ヒントは「どこが決まるか」に加えて **なぜそう決まるか** を説明します。
盤面の実際の数字や本数を使った文章（例:「上から 3 番目・左から 2 番目のマスの 3 は、
まわりにもう線が 3 本。必要な数がそろっているので、残りの辺にはもう引けません」）と、
根拠になっているマス・交点・辺のハイライトが出ます。
そのまま置くことも、自分で考えることも選べます。

ヒントには必ず **いまの盤面から一歩ずつたどれる証明** が付いています。

- 盤面を見ただけで基本ルールが 1 つ当てはまる手は、そのルールと根拠の印を示します
- そうでない手は背理法で示します。「ここを線と仮定する → 3行2列のマスの 3 は × が 1 本
  → 残りは線 → … → 矛盾: 4行3列の点が行き止まりになる」のように、**矛盾までの手順を
  一手ずつ** 並べます（「根拠を一手ずつたどる」）。仮定の中でさらに仮定が要るときは、
  その中身も字下げして全部書きます
- 仮定したときに決まっていく印は、盤面に点線と緑の × で重ねて表示します
- 手順の各行は、数字の本数・交点の線は 0 本か 2 本・輪はひとつだけ、のどれか 1 つだけで
  決まります。各行には「何が分かっていたからそう決まったか」（前提の辺）が付いていて、
  `checkProof` がそれだけを見て **一から検算** します。検算に通らない証明は出しません
- 候補が複数あるときは、手順のいちばん短いものを選びます

## 画面の配置

使う頻度で置き場所を分けています。

| 頻度 | 置き場所 | 中身 |
| --- | --- | --- |
| 解いているあいだずっと | 盤面のすぐ下の 1 列（広い画面では盤面の右） | 線／バツの切り替え（左端）・もどす・すすむ・チェック・ヒント・定石 |
| ときどき | 右上の ? と 本のボタン | 遊び方（図つきのルール・操作の説明）・定石一覧 |
| 解いている最中には使わない | 右上の「⋯」（メニュー） | この問題（難易度・問題コード・問題リストに入れる・ぜんぶ消す）・新しい問題（大きさ・むずかしさ・写真から作る・問題集・問題リスト）・そのほか（解いた履歴・設定） |

右上の 3 つ（遊び方・定石一覧・メニュー）は、どれも画面の右から出るパネルです。左の暗い部分か Esc で閉じます。

スマホを横にしたとき（横長で高さが低い画面）は、盤面を左に画面の高さいっぱいで置き、タイトル・ボタン・ヒント・定石のカードを
右の列にまとめます。右の列が長くなって送っても盤面は動きません。ノッチのある機種では、左右の切り欠きを避けます。

メニューの最初の画面は、いまの問題のことと、そうでないことを分けて並べています。文言は短く、説明は添えません。

- **この問題**：難易度（「難易度　ふつう」と 1 行、押すとくわしい分析）・問題コード（共有・読み込み）・問題リストに入れる・ぜんぶ消す
- **新しい問題**：大きさ・むずかしさ・作る、写真から作る（撮影・選ぶ）、問題集、問題リスト
- **そのほか**：解いた履歴・設定

問題リスト・問題コード・設定・難易度の分析は、メニューの中の別の画面です。左上の ← か Escape で最初の画面へ戻り、
右上の × で閉じます。

解き終わると盤面に「つぎの問題」が出ます。そこで次の大きさ・むずかしさも選べるので、続けて遊ぶときはメニューを開かなくて済みます。

時間と自己ベストは、解き終わったときの「完成！」に出します（解いている最中は出さず、その分ヒントの場所を広く取ります）。

ヒントの説明は、ヒントを押したボタンのすぐ下に開きます。ヒントを出しているあいだにもう一度ヒントを押すと消えます。背理法の手順（「根拠を一手ずつたどる」）は最初は必ず畳んであり、要約に矛盾の中身を書きます。説明は短い文にしてあり、
画面の下端に収まらないときは文字を少しずつ小さくして（最小 7 割）、スクロールせずに読めるようにします。
それでも収まらないほど長い手順のときだけ、ヒントの欄の中で送れるようにします。ほかにも決められる手があれば、‹ › （スマホなら左右にはらう）で
別のヒントへ送れます（分かりやすい順に最大 10 件。同じ理由で決まる手は 1 件にまとめます）。

ヒントの右の「定石」を押すと、同じ場所に **いま使える定石だけ** がカードで並びます
（出番の多い順）。左右にスワイプ（PC なら ‹ › か矢印キー）で切り替えます。欄の見出しには、いま見ているカードの定石名と当てはまる場所の数が出ます。カードを見ただけでは
盤面のどこに効くかは出さないので、まずは自分で探せます。カードの下のボタンは 3 つです。

- **候補**：その定石が当てはまる位置（決まる辺）と、そこに入る線か × かを盤面に光らせます。もう一度押すと消えます
- **当てはめる**：当てはまる場所すべてに、まとめて置きます
- **やめる**：定石のカードを閉じます置いたあとは
数え直して、同じカードがまだ使えればそのまま開いています。カードの「一覧」から、
全部の定石を図と説明つきで見られるサイドバーを開けます。

## 写真から問題を作る

メニューの「写真を撮って作る」（その場で撮影）か「写真から作る」（写真アプリの画像やスクリーンショット）で、
紙や画面に載っている問題をそのまま取り込めます。
Mac などのパソコンでは「写真を撮って作る」を押すとカメラの映像が出るので、盤を写して「撮る」を押します
（ブラウザがカメラを使う許可を聞いてきます。カメラが 2 台以上あれば切り替えられます）。

1. **四隅を合わせる** — 盤の点を写真から探し、いちばん外側の 4 つの点に丸を置き、マス数も見積もります。
   ずれていれば丸をドラッグし、マス数を直します（重ねて描くマス目の線が見当になります）
2. **数字を読み取る** — 四隅から射影変換を求めて傾きや遠近のゆがみを戻し、各マスの内側だけを切り出して
   0〜3 を見分けます。**印刷の数字も手書きの数字も** 読めます。ゆがみを戻した写真の上に、読み取った数字を
   各マスの右上に重ねて出すので、写真の字と見比べられます。自信の無いマスは赤い点線で示し、押すと
   空白 → 0 → 1 → 2 → 3 と直せます
3. **論理だけで解けるかを自動で確かめる** — 直すたびに裏のワーカーで確かめ、
   「論理だけで解けます（答えは 1 つ）」のときだけ「遊ぶ」「リストに入れる」が押せます。
   数字どうしの矛盾や、論理だけでは解き切れない（答えが複数ある・当てずっぽうが要る）ときは、その旨を出します。
   そのときは、自信の低いマスを 1 つずつ次に近い数字へ変えて確かめ直し、解けるようになる直し方が見つかれば
   「3行5列の 2 を 3 にすると、論理だけで解けます [3 に直す]」と提案します

読み取りは外部のライブラリやサーバを使わず、ブラウザの canvas だけで行います（`src/ui/image-reader.js`）。

- 点は「まわりより目立って暗い、小さく丸いかたまり」として探し、いちばん多い大きさのものだけを残します
  （明るさのむら・ぼけ・ざらつきに強くするため、ならしてから周囲の平均と比べます）
- となりの点へのずれの向きから格子の 2 方向を決め、点をたどって (列, 行) の番号をふり、
  **全部の点から最小二乗で射影変換を当てはめて** 四隅を出します。指やボタンで一部の点が隠れていても四隅が決まります
- 数字は、マスごとの紙の白さから測って暗いところを文字とみなし、小さなごみや縁にかかる点を消してから
  （`cleanMask`）、文字を囲む四角を 20×20 に面積平均で縮めます（`src/ui/digit-features.js`）
- 印刷の文字は、いくつかの書体で描いた型との相関が高ければそれで決めます
- それ以外（手書きなど）は、小さなニューラルネット（400 → 64 → 4、重みは 8 ビットに詰めて約 35KB の
  `src/ui/digit-model.js`）で見分けます。線の太さを変えた 3 通り（そのまま・細く・太く）の確率を平均するので、
  細いペンでも太いマーカーでも読めます

#### 手書き数字のネットの学習

MNIST（手書き数字のデータ。Yann LeCun, Corinna Cortes, Christopher J.C. Burges、CC BY-SA 3.0）の 0〜3 と、
いろいろな書体で描いた印刷の数字で学習しています。写真の読み取りと同じ前処理を通し、世代ごとに回転・斜め・
縦横比・線の太さ・しきい値を変えて学習します。

```
node tools/render-digits.js printed-digits.json         # 印刷の数字を描く（Playwright が要る）
node tools/train-digits.js <MNIST のフォルダ> 12 printed-digits.json   # src/ui/digit-model.js を書き出す
```

確認用データ（学習に使っていない MNIST の 0〜3）での正答率は 99.3%、形を変えたもので 99.0% です。
手書きふうの盤（確認用データの数字を、点を打った紙に書いて撮ったように傾け・ぼかし・明るさむら・ざらつきを
付けたもの）では、約 1,100 個の数字のうち読み間違いは 1% ほどで、その多くは人が見ても迷う字でした

確かめは作問と同じ `checkPuzzle`（`src/core/puzzle.js`）で、`solveLogical` で矛盾とむずかしさの目安
（仮定なし／1 段／2 段）を出し、`solveWithProofs` と同じ証明探しで最後まで解き切れるかを確かめます。

### 問題リスト

メニューの「問題リスト」に、写真から作った問題や、いま遊んでいる問題（「いまの問題をリストに入れる」）を
入れておけます（端末の中に最大 200 問。同じ問題は 1 つにまとめます）。「遊ぶ」でいつでも開けます。

## 定石一覧

「こういう配置になったら、こういう理由でここが確定する」を図つきで並べた
一覧です。ゲーム画面の「定石」カードの「一覧」からサイドバーで開けます
（`patterns.html` は同じ内容の単独ページ）。
45 個の定石を、先頭の **定番** と、**出番の多さで 3 段**（よく使う＝1 問あたり 5 本以上／ときどき使う＝1 本以上／
たまに使う）に分け、段の中も出番の多い順に並べています。ゲーム中のサイドバーでは「たまに使う」と
「図の読み方」は畳んであります。カードには分類と出番の多さ
（1 問を解くあいだにその定石で決められる辺の本数の実測平均）を出します。

出番は `node tools/pattern-stats.js` が実測して `src/core/pattern-stats.js` に書き出します。
7×7・10×10 をやさしい・ふつう・むずかしいで 4 問ずつ、ヒントどおりに最後まで解き、
途中の盤面ごとにその定石で埋められる辺を集めて、1 問ごとに重複なしで数えます
（盤面ごとの「使えたかどうか」で数えると、すぐ使われてしまう易しい定石ほど少なく見えるため）。
seed は固定なので、何度走らせても同じ値になります。定石を足したら走らせ直してください
（実測値の無い定石があるとテストが落ちます）。

ゲーム画面のサイドバーには **「いま使える定石だけ表示」** の切り替えがあり、オンにすると
いまの盤面に当てはまる場所がある定石だけが残ります（盤面が変わるたびに絞り直し、
状態は次に開いたときも保たれます）。

うち 12 個は型の照合ではなく、**ルールそのものを盤面全体に適用**します
（`match` フィールド）。

| 定石 | ルール |
| --- | --- |
| 交点に線が 2 本集まったら、残りは ×（直線の横も ×） | 交点の線は 0 本か 2 本（分かれ道の禁止） |
| 線の端は、行ける方向が 1 つならそこへ伸びる | 同上のうち、行き止まりの禁止 |
| 行き止まりになる辺は ×（交点の 3 方向が × なら残りも ×） | 同上のうち、1 本だけ出る形の禁止（縁なら 2 方向、角なら 1 方向） |
| 数字の本数がそろったら、残りは × | 数字はまわりの線の本数（どの数字・どの向きでも） |
| 残りを全部使わないと届かないなら、残りは線 | 同上（1 の 3 辺が ×、2 の 2 辺が ×、3 の 1 辺が × など） |
| 閉じ込められた場所には入れない | 線は輪の一部（どこかで戻ってくる） |
| 小さな輪を閉じてはいけない | 輪はひとつだけ |
| 近道で輪を閉じてはいけない（まだ線の要る数字がある） | 輪はひとつだけ（線か × を置くと 12 手以内に輪が閉じて数字が残るなら、その逆に決める。1 マスのまわりを回るしかない袋小路も含む） |
| 数字のまわりをまとめて考える（角の偶奇） | 数字の本数と、角の点の線は 0 本か 2 本（数字のマスの 4 辺と角から外へ出る辺を総当たり） |
| となりの数字といっしょに考える | 同上（となり・斜めに並ぶ 2 つの数字をまとめて総当たり） |
| 1 の角の外側がふさがれたら、その角の 2 辺は × | 交点の線は 0 本か 2 本（盤の縁や角の点でも） |
| 3 の角の外側がふさがれたら、その角の 2 辺は線 | 同上 |

交点まわりと数字の本数の定石は、もとは 1 つの向きの型でしたが、型では
直線の横・まっすぐ進む線の端・盤の縁の点・別の数字や向きを拾えなかったため、
ルールそのものを当てはめるようにしました（どの向き・どの数字でも働きます）。「閉じ込められた場所」は、
× を取り除いた図で橋になっている辺（通ると戻ってこられない辺）を × にします。
交点ごとの数え上げでは届かない形が決まります。

定石の候補は、参考文献が挙げる配置を出発点に、盤で総当たりして
「何が確定するか」を機械的に洗い出したものです。
採用するかどうかは次のように決めています。

- **定番は重なっても載せ、一覧の先頭に並べる。** 「0 のまわりは全部 ×」「角の 1」「角の 3」「角の 2」「3 と 3 がとなり合う」「3 と 3 が斜めに並ぶ」「0 のとなりの 3」「0 と 3 が斜めに並ぶ」「3 と 3 のあいだに 0」「3 が 3 つ並ぶ」の 10 個は、よく知られた形なので、ほかの定石と結論が重なっていても「定番」として先頭に並べます（`popular`）
- **ほかの定石 1 つの特別な場合（論理的に同じもの）は載せない（定番を除く）。** 一覧の整理で、
  「交点に集まる線は 0 本か 2 本」（交点の 3 つの定石をまとめただけ）、「0 のまわりは全部 ×」
  （「数字の本数がそろったら」の 0 の場合）、「縁の交点は、2 方向が × なら残りも ×」
  （「行き止まりになる辺は ×」の縁の場合）、「角の 1」「角の 3」（「1 / 3 の角の外側がふさがれたら」の
  盤の角の場合）、「3 が 3 つ並ぶ」（「3 と 3 がとなり合う」だけで結論が全部出る）、
  「3 と 3 のあいだに 0」（「0 のとなりの 3」だけで出る）の 7 個を外しました。
  定石の図の盤で、ほかの定石 1 つだけを当てはめて結論が全部出ないことをテストで確かめています
- **ほかの定石の組み合わせで届くものは「近道」として載せる。** 何手もかかる推論を 1 つの形で
  見抜けるので残し、説明に「近道: 「A」・「B」を組み合わせれば…」と添えます（`combines`）。
  その組み合わせだけで本当に同じ結論に届くことを、テストで確かめています（12 個）
- それ以外は、いまの一覧をくり返し当てはめても導けない結論を持つものだけを足すとなり合う 2 数・斜めの 2 数・3 つ並び・1 マス空けた 2 数・
角と縁の数字・数字と印の組み合わせを一通り調べ、確定するものだけを採用しました。
逆に、1 と 1 / 1 と 2 / 2 と 2 / 2 と 3 のとなり合わせ、縁の 1・2・3 などは
**それだけでは何も確定しない**ことも確かめています。

### ヒントの証明から見つけた定石

背理法のヒントには、矛盾までに使った数字と印がすべて記録されています（前提）。
`node tools/mine-patterns.js` は、問題をヒントどおりに解きながら次の手を拾います。

1. 背理法のヒントで、いまの定石をくり返し当てはめても届かない辺
2. 証明が「輪はひとつだけ」を使っていない（盤面全体に依存しない）もの
3. 盤の縁の点を使っていない（どこにでも置ける）もの

その証明が使った数字と印だけを取り出し、回転・反転をそろえて数えると、24 問のヒント
3884 手のうち、定石では届かない内側の形は 116 手・42 種類ありました。複数の問題に
くり返し出てくる形を、その形だけを置いた盤でも定石では届かないことを確かめてから、
6 個を足しています（`origin: 'hint'`）。

このうち「片側が × の 2 の角に、外から線が来た」は、線が × の辺と直角に来る形と平行に来る形の
2 通りがあり、回転・反転では互いに移りません。はじめは片方しか載せておらず、実際の盤面で
当てはまらない場面があったため、もう一方を `alt`（同じ定石の別の形）として足しました。
`expandForms` で別の形も 1 つの定石として展開し、同じ検証を通しています。

| 定石 | 出てきた問題 |
| --- | --- |
| 片側が × の 2 の角に、外から線が来た（線が来る向き 2 通り） | 12 問 |
| 片側が × の 2 の角が、× でふさがれた | 5 問 |
| 2 辺が × の 1 の角に、外から線が来た | 3 問 |
| 3 の 2 辺に 1 がとなり合う | 6 問 |
| 片側が × の 2 と、斜めの 3 | 4 問 |
| 2 辺が × の 1 と、斜めの 3 | 3 問 |
| となり合う 1 と 1 は、境目の先が × なら境目も ×（大きな盤の洗い出しで追加） | 2 問 |

足したあとは、定石で届かない内側の形が 56 手・32 種類に減り、残りはどれも 2 問以下にしか
出てこないため見送りました。どれも他の定石と同じ検証（総当たり・余白つきの盤・
8 方向）を通り、さらに **ほかの定石をどう組み合わせても結論に届かない** ことをテストで
確かめています。

### ステージをくり返して定石を増やす試行

`node tools/pattern-loop.js 100` は、5 × 5〜15 × 15 とやさしい〜むずかしいを順に変えながら 100 ステージを作り、
**定石だけで解き進め、行き詰まったらその盤面のヒントの証明から定石の候補を取り出す**（盤の縁・角の形も含む）、
を続けます。2 問以上で出てきた形はその場で採用して、以後のステージで定石と一緒に使います。

100 ステージで行き詰まりは 504 回（やさしいは 0 回）、採用した形は 49 個でした。ところが、試行に使っていない
30 問で確かめると、49 個を全部足しても行き詰まりは 369 → 331 回（1 割減）にとどまりました。行き詰まる形は
ばらばらで、1 つの形が効く場面はわずかです。

そこで 49 個の形をながめると、多くは「数字の角に外から線が来るか来ないか（角の偶奇）」と数字の本数の組み合わせ
でした。形ではなくこの考え方そのものを、数字のマス（と、となり・斜めの数字の組）のまわりで総当たりする
2 つの定石にしました。これだけで同じ 30 問の行き詰まりは 369 → 180 回（半分）になり、49 個のうち 32 個の形も
これで拾えます。15 × 15 の「ふつう」で、ヒントはあるのに使える定石が 1 つも無い場面は 29 → 8 に減りました。
残りは 13 手以上続く連鎖です。

### 「輪はひとつだけ」に頼る定石

となり合う 3 と 3 のまん中の辺は、閉路禁止（輪はひとつだけ）があって初めて
線に決まります。2 マスをまとめて囲む長方形の輪でも 3 と 3 自体は成立するため、
その長方形が答えそのものになりうる盤面（ほかの数字がすべて 0 か、数字が無い）
では決まりません。照合ではこの条件を毎回判定しています
（`smallLoop` / `loopConclude`）。

ほかに同じ理屈が効く定石がないかを機械的に洗い出しました。

- 当時収録していた 34 個すべてについて、遠くに数字を 1 つ足した盤面と足さない盤面で
  確定する辺を比べた結果、**追加で確定したのは「3 と 3 がとなり合う」だけ**
- 「小さな輪がその数字をぴったり満たしてしまう」形（1〜6 マスの 12 種類）を
  総当たりした結果、閉路禁止で何かが増えるのは横 2 マス（3-3）と
  T 字 4 マス（3-1-3-3）のみ。後者は他の定石だけで同じ結論に届き、
  40 問中 0 回しか現れないため収録していない

定石ごとに「当てはめる」ボタンがあり、押すと **いまの盤面からその定石が
使える場所をすべて探して、決まる印を引きます**。ボタンの数字は当てはまる
場所の数で、盤面が変わるたびに数え直します（全定石を数えても 1ms 未満）。

当てはめは `src/core/pattern-match.js` が行います。定石は 1 つの向きだけ
書いておき、回転・反転の 8 通りに変換してから盤面を走査します。
角の定石は盤の角に合わせたときだけ使います。

定義の `rows` / `cols` は図を見やすくするための枠で、まわりの余白マスは
推論に使っていません。そのため照合では枠ではなく、**実際に参照する数字と辺**
だけが盤に収まるかを見ます（枠ごと収まることを求めると、盤の端にある 0 などを
取りこぼします）。

載せている内容は `src/core/patterns.js` に宣言的に書かれていて、
`tests/patterns.test.js` と `tests/pattern-match.test.js` が毎回検証しています。

- 小さな盤では **総当たりで全解を調べ、反例が 1 つも無いこと** を確認
- まわりに余白を足した大きな盤では、論理ソルバで **否定すると矛盾すること** を確認
- 前提そのものに解があること（空虚な真になっていないこと）も確認
- 回転・反転した 8 通りそれぞれについても同じ確認
- 盤の端にかかる置き方も含め、置ける位置すべてで結論が確定することを総当たりで確認
- 結論の一部が盤からはみ出す置き方でも、盤に残る結論が確定することを総当たりで確認
- 生成した問題に全定石を当てはめ続け、**埋めた辺が 1 本も正解と食い違わないこと**
  を確認（実測: 30 問・1817 本を埋めて食い違い 0）
- どの定石も、その形を盤に作れば必ず見つけられることを確認

この検証の過程で、よく「隣り合う 3 と 3 のあいだの辺は線になる」と
説明される定石が成り立たないことが分かりました（2 マスをまとめて囲む
長方形の輪が反例になります）。ページではその点も注記しています。

## 起動

```sh
npm start          # http://localhost:8080/ で開く
```

`file://` で直接開くと Web Worker と ES Modules が動かないため、必ず HTTP で配信してください。

## 公開

`npm run build:site` が、配信に必要な `index.html` と `src/` だけを `_site/` に集めます。
テストや開発用ツールは含まれません。

### Cloudflare（既定）

`.github/workflows/cloudflare.yml` が、既定ブランチへの push でテストを走らせたあと
`wrangler` で Cloudflare Workers（静的アセット配信）へデプロイします。
設定は `wrangler.jsonc` の 1 ファイルだけです。

必要なのはリポジトリのシークレット 2 つです。
**Settings → Secrets and variables → Actions** に登録してください。

| 名前 | 中身 |
| --- | --- |
| `CLOUDFLARE_API_TOKEN` | Workers のデプロイ権限を持つ API トークン |
| `CLOUDFLARE_ACCOUNT_ID` | Cloudflare ダッシュボードのアカウント ID |

API トークンは Cloudflare の **My Profile → API Tokens → Create Token** から、
テンプレート **Edit Cloudflare Workers** で作れます。
公開先は `https://gridloop.<サブドメイン>.workers.dev` です。

シークレットが未設定のあいだは、デプロイ手順だけを黙ってスキップします（CI は緑のまま）。

ダッシュボードから Git 連携で Cloudflare Pages に繋ぐ方法でも動きます。
その場合のビルド設定は次のとおりです。

- ビルドコマンド: `npm run build:site`
- ビルド出力ディレクトリ: `_site`

### ログイン（Google アカウント）とサーバー

`server/worker.js` が `/api/` を受け、それ以外は静的ファイルをそのまま返します（`wrangler.jsonc` の `run_worker_first`）。
ログインした人ごとに、問題リスト・解いた履歴（解いた問題・時間・ヒントの回数）・自己ベスト・途中の盤面を
Cloudflare D1（データベース名 `gridloop`、スキーマは `migrations/`）に持ち、どの端末からでも同じものが見えます。

- ログインは Google の「Google でログイン」ボタンでもらう ID トークンを、サーバーが Google の公開鍵で確かめてから
  （署名・発行元・宛先・期限）、こちらのセッションを HttpOnly の Cookie で出します（60 日）。パスワードは扱いません。
- ゲストのあいだは、問題リストと解いた履歴は使えず、押すとログインを促します。遊ぶこと・自己ベスト・途中の盤面は端末の中で続けられます。
- 初めてログインしたときは、その端末にあった問題リスト・自己ベスト・途中の盤面をアカウントへ取り込みます（1 回だけ）。
- 途中の盤面は、動かすたびに少しまとめてから送り、閉じるときにも送ります。ほかの端末で進めたほうが新しければ、
  開いたときにそちらへ切り替えます（その端末でまだ手を動かしていないときだけ。送られてきたリンクで開いた問題はそのまま）。

使うには、Google Cloud Console で **OAuth 2.0 クライアント ID（ウェブ アプリケーション）** を作り、
「承認済みの JavaScript 生成元」に公開先（例 `https://gridloop.<サブドメイン>.workers.dev`）を入れて、
そのクライアント ID を `wrangler.jsonc` の `vars.GOOGLE_CLIENT_ID` に書きます（秘密の値ではありません）。
空のあいだは、ログインのボタンの代わりに「準備中」と出し、ゲストとしてだけ遊べます。

データベースの変更は、公開のたびに `wrangler d1 migrations apply gridloop --remote` で当てます（GitHub Actions でも同じ）。
手元で試すときは `npm run build:site` のあと `npx wrangler dev`（D1 は手元の写しを使います）。

### 問題集と管理画面（`/admin`）

管理者は `/admin`（`admin.html`）で問題集を作り、問題をまとめて登録できます。管理者は `wrangler.jsonc` の
`vars.ADMIN_USER_IDS`（Google のアカウント ID、カンマ区切り）か `ADMIN_EMAILS` で決めます。管理者でなければ画面もサーバーも使えません。

- 問題集：名前・説明・公開のしかた（非公開／管理者のみ／公開）。消すと中の問題も消えます。
- まとめて登録：画像・画像をまとめた zip・PDF を落とすと、1 枚（PDF なら 1 ページ）を 1 問として、
  写真から作るときと同じ仕組みで盤の四隅とマス数を見つけ、数字を読み、論理だけで解けるかまでブラウザの中で確かめます。
  解けたものだけを「解けたものを足す」で登録します。うまく読めなかったものは「直す」で、写真から作るときと同じ画面で直せます。
  - zip の中は、ファイル名の数の順（1, 2, …, 10）に並べます。名前が Shift_JIS の zip も読めます（`src/ui/zip.js`）。
  - PDF は pdf.js（`src/vendor/pdfjs`、Apache-2.0）でページを画像にします（`src/ui/pdf-pages.js`）。
  - 同じ問題集に同じ問題はもう一度入りません（飛ばした数を知らせます）。
  - 盤は縦横 50 マスまで読めます（ニコリの大きな盤 20×36 も入ります）。問題コードで扱える大きさも同じです（`MAX_SIZE`）。
- ランダムに作る：縦・横・問題数を決めて「作る」と、その大きさの問題をブラウザの中で作って一覧に並べます。
  むずかしさは「いろいろ」なら入門〜鬼を同じくらいずつ、やさしい順に作ります（1 つの段だけも選べます）。
  時間内に狙いの段が作れなかったものは、本当の段を付けて知らせます。作った問題にも目安が付きます。「止める」で打ち切れます。
- 入っている問題：順番の入れ替え・外す・遊んで確かめる（新しいタブで開く）。
- 問題ごとに、5 段階の難易度と数字の個数のほか、次の目安も持ちます（`problemStats`、`src/core/difficulty-report.js`）。
  目安を持たずに登録した問題は、管理画面でその問題集を開いたときに計算して埋めます。

  | 目安 | 意味 |
  | --- | --- |
  | 線の本数 | 答えの輪の長さ |
  | 定石 % | 定石（ふつうの定石・読みの定石）だけで決まる辺の割合 |
  | 仮定なし % | 最初に仮定が要るまでに決まる割合。仮定が要らなければ 100% |
  | 仮定の回数 | 仮定（「ここに線を引いたら…」と考えて矛盾を見る）が要る回数 |
  | 最長の読み | いちばん長い読み（仮定してから矛盾が出るまで）の手数 |
  | 行き渡り % | 線の行き渡り率。4 辺のどれかが線になるマスの割合（角だけ触れるマスは数えない） |
  | 最大の空き地 % | 線の通らないマスが上下左右でつながったかたまりのうち、いちばん大きいもの（盤の %）。行き渡り率が同じでも、空きが固まっているか散っているかが分かる |

  問題ごとに出どころ（スキャン＝画像・zip・PDF から読み取ったもの／自動作問＝このアプリのランダム作問）も持ちます。
  「問題集をくらべる」で、問題集ごとに目安を平均し、全体・難易度の内訳・大きさごとに並べます。
  開いたとき、目安が欠けている問題を全部の問題集から探して計算し直します。

- **作問ロジックの版**（`src/core/generator.js` の GENERATORS）：ランダム v1（最初の作り方）・ニコリ風 v1（点対称・盤いっぱいの輪・
  ニコリ風の条件）・ニコリ風 v2（数字をむらなく・3 を残す・入門にも考える手）・ニコリ風 v3（数字の内訳と手触りをニコリに寄せる：
  考える手が多すぎれば難易度を保って数字を戻し、山場が後半の問題を選ぶ。src/core/feel.js の feelProfile で測る）。
  ニコリ風 v4（v3 に加えて、むずかしさごとに考える手の目安を変えて入門・やさしいを軽くし、考えさせられた場所の近くから数字を戻す。
  20 問ずつの遊び比べでは v3 とほぼ変わらなかった）。ニコリ風 v5（v3 を元に、0 を固めずに離して置き：ニコリの 0 は 8 割がまわり 2 歩以内に
  ほかの 0 が無いが、v3 は半分だけで、固まった 0 を順に消す × だけの作業が長く続いていた。数字を戻すときは 3・2 から戻し、
  候補を選ぶときに作業の続く区間（src/core/feel.js の workRun）も見る）。ニコリ風 v6（v5 に加えて、数字を戻すときは
  考えさせられた場所の近くの 3・2 から戻し、ふつうの考える手の上限を 12 から 11 に下げる。少ない数字で重さを整える）。
  最初に選ばれる作り方は v3 のまま。古い版もそのまま作れるように残してある
  （同じ乱数の種なら、版を足す前と同じ問題になる）。「ランダムに作る」で作り方を選び、問題ごとに版を持つ
  （book_problems.generator、0007_generator.sql。すでにあった自動作問は名前から版を付けた）。
  問題一覧の「作り方」の列・絞り込み、問題の詳細、くらべる画面の「作り方どうし」（目安の平均・難易度の内訳・大きさごと）で比べられる。
- **ニコリ風**：ニコリの問題集（とことん01 の 99 問）の特徴を条件にしたもの（`src/core/nikoli.js`）。
  数字の配置が点対称・数字 50% 未満・線／マス 0.80 以上・行き渡り 80% 以上・最大の空き地 4% 以下・定石 95% 以上・
  仮定 3 回まで。とことん01 は 99 問中 98 問が満たし、ふつうのランダム作問は 20 問中 4 問だった。
  「ランダムに作る」で「ニコリ風」を選ぶと、輪を盤いっぱいにくねらせ（輪の長さがマス数の 0.85〜0.97 倍）、
  数字を点対称の組で削り、条件を満たすものだけを作る。入門・やさしいは定石だけで解けるよう数字を多めに残すので、
  「数字 50% 未満」だけは問わない（点対称と輪の形は守る）。鬼は仮定が多すぎるので作らない。
  大きな盤は時間がかかる（36×20 で 30 秒ほど）。
  遊び比べ（10×10 を 10 問ずつ）で分かったニコリとの差をもとに、数字は密なところ・1 や 0 から先に削り
  （3 を残しやすく）、空の行・列や数字のない 3×3 ができる削り方はせず、仕上げに数字の詰まった行・列を間引く。
  入門・やさしいでも少し先を読む深さまで削ってから戻し、少し先を読む手（src/core/feel.js）が 3 回以上ある問題だけにする。
  問題一覧（絞り込み・列）・問題の詳細（条件ごとの ○×）・くらべる画面（問題集・大きさごとの割合）に出す。
- **問題リストに自動で入れる**：ログイン中は、写真から作って遊び始めた問題と、解いた問題を問題リストに自動で入れる。
  解いた問題には初めて解いた日時といちばん速い時間も残す（入っていたときの出どころは引き継ぐ）。
- **問題集を公開する**：管理画面で問題集ごとに公開のしかたを 3 段階から選ぶ。非公開は管理画面でだけ見える。
  公開にすると、ログインした人がゲームのメニューの「問題集」で遊べる（ゲストにはログインをすすめる）。
  管理者のみにすると、管理者だけがメニューの「問題集」で遊べる（公開する前に遊んで確かめる。名前の横に「管理者のみ」と出る）。
  books.published に 0（非公開）・1（公開）・2（管理者のみ）で持つ（表の形は変えていない）。問題集の一覧（解いた数の帯）→ 問題の一覧
  （1 問 1 行。解いた問題は時間・ヒントの回数・日付）と進み、好きな問題から始められる。解いたら完成のお知らせに
  問題集の名前と何番かを出し、「次の問題へ」（まだ解いていない次の問題）か「メニューへ」（問題集の問題の一覧）を選べる。
  問題集で遊んでいるあいだは、上の帯に問題集の名前と何番か（押すと問題集の問題の一覧）を出し、
  URL は問題集の何番かを指すパーマリンク（`?book=ID&n=番号`）にする。開き直しても、ほかの端末で開いても同じ問題になり、
  途中まで解いて保存してある問題なら続きから（ログインしていなければログインをすすめる）。問題集の外の問題では、
  これまでどおり問題コード（`?p=`）。どの問題集の問題を遊んでいるかは端末にも覚えておく。
  解いた印は D1 の book_solved に持つ（0006_book_solved.sql）。ゲームで解いて履歴を送ると、
  その問題コードが公開中（管理者のみを含む）の問題集の問題と同じなら、サーバーが印を付ける（時間はいちばん速いもの）。
- **問題一覧**（`/admin/problems`）：全部の問題集の問題を 1 つの表に並べます。問題集・出どころ・大きさ・むずかしさで
  絞り込み、列の見出しで並べ替えられます（絞り込みと並べ替えは URL に残ります）。行を押すと詳細へ。
- **問題の詳細**（`/admin/problem?id=…`）：盤（答えも見られる）、問題集の中での位置と前後の問題、情報と目安、
  くわしい解き味（メニューの「この問題の難易度」と同じ分析）を出します。

## 「必ず論理的に解ける」の担保

作問は次の手順です。

1. 内側マスの集合をランダムに育て、その境界がつねに **単一の閉ループ** になる変更だけを採用する
2. できた輪からすべてのマスの数字を求める
3. 数字をランダムな順に 1 つずつ消し、消すたびに **論理ソルバだけで最後まで解けるか** を確かめる。
   解けなくなる数字は元に戻す

ソルバが使う推論は次のものだけで、探索による総当たりは含みません。

| ルール | 内容 |
| --- | --- |
| R1 数字の充足 | 線が数字に達したら残りは ×、残り全部を使わないと届かないなら残りは線 |
| R2 交点の次数 | 各交点の線は 0 本か 2 本。端は必ずもう 1 本つながる |
| R3 閉路の禁止 | 全体が完成しないのに輪を閉じてしまう辺は × |
| R5 内側と外側 | どのマスも輪の内側か外側。線をまたぐと入れ替わり、× をまたぐと同じまま（盤の外は外側）。2 つのマスの関係が確定した辺をたどって分かれば、間の辺も決まる |
| R4 背理法 | ある辺を仮定すると R1〜R3・R5 だけで矛盾する → 反対の値に確定 |

R5 はニコリの大きな盤（20×36 など）でよく要る考え方です。これが無いと、人には論理で解ける問題でも「論理だけでは解き切れない」と判定していました。
R5 を入れたことで、以前は仮定 2 段が要った問題の一部が仮定 1 段で解けるようになり、5×5 の「鬼」は時間内に作れないことがあります（そのときは本当の難易度を知らせて出します）。

### 難易度（解き味で決める）

難易度は、人が解くときに **どの段の考え方まで要るか**（解き味）で決めます。解き味は
`src/core/difficulty-report.js` が、空の盤から浅い考え方を優先して解き進めて調べます（下の「この問題の難易度」）。

| 難易度 | 要る考え方 | 数字の残り（目安） |
| --- | --- | --- |
| 入門 | 定石を当てはめるだけ | 約 5 割 |
| やさしい | 定石＋基本ルールの組み合わせ（定石には無いが盤面を見れば決まるもの） | 約 4 割強 |
| ふつう | ＋読みの定石（数字のまわりをまとめて考える・近道で輪を閉じない など。仮定は要らない） | 約 4〜5 割 |
| むずかしい | ＋仮定 1 段（1 か所を仮定して矛盾を見る） | 約 4 割 |
| 鬼 | ＋仮定 2 段（仮定の中でさらに仮定する） | 約 3〜4 割 |

どの難易度も「その段が **ちょうど** 要る」問題だけを出します（1 つ下の考え方では解けず、その段までで解ける）。
作り方は次のとおりです。

1. 輪を作り、全部の数字から始めて、ソルバ（背理法の深さ：入門・やさしいは 0、ふつう・むずかしいは 1、鬼は 2）で
   解ける限り数字を削る。削った順番を覚えておく。鬼は 2 段で削るのが重いので、鬼に届いたところで止める
2. できた問題の解き味を調べる
3. 狙いより難しければ、削った順番の途中まで戻す（数字を足し戻す）。どこまで戻すかは二分探索で探す
4. 狙いより易しければ、輪から作り直す

以前は「背理法を何段まで使ってよいか」だけで難易度を決めていたため、ふつうとむずかしいが同じ問題になったり、
むずかしいが仮定なしで解けたりしていました。いまは解き味で確かめてから出すので、名前と中身がずれません。
鬼の大きな盤は作るのに時間がかかります（15 × 15 で 10〜40 秒ほど。次の問題は裏で先に作っておきます）。
時間内に作れなかったときは、作れたうちで狙いにいちばん近い問題を、本当の難易度を付けて出します。

問題コードの難易度の文字は、入門 `b`・やさしい `e`・ふつう `n`・むずかしい `h`・鬼 `x` です。
写真から作った問題にも、同じ分析で難易度を付けます。確かめの結果に出る「ふつう」などの難易度を押すと、
メニューの「この問題の難易度」と同じくわしい分析（内訳の帯グラフ・使う定石・仮定の要る場面・難易度の段の説明）が開きます。
その問題で遊び始めると、メニューの「この問題の難易度」も調べ直さずにすぐ出ます。

### この問題の難易度（メニュー）

難易度の名前（やさしい・ふつう・むずかしい）は作るときの上限で、1 問ごとの解き味までは表しません。
そこでメニューの先頭に、いまの問題の解き味（「ふつう」など）を 1 行で出し、押すと、空の盤から解き進めて調べた結果をくわしく出します（`src/core/difficulty-report.js`、
裏のワーカーで計算）。浅い考え方で進める限り深い考え方は使わず、行き詰まったときだけ 1 つ深くします。

1. ふつうの定石（形を見れば決まるもの）
2. 基本ルールの組み合わせ（定石には無いが、盤面を見ただけで決まるもの）
3. 読みの定石（数字のまわりをまとめて考える・近道で輪を閉じない など、局所的に場合分けするもの）
4. 仮定 1 段（1 か所を仮定して矛盾を見る）
5. 仮定 2 段（仮定の中でさらに仮定する）

決まった辺がどの段によるかを帯グラフで示し、ひとことの判定（「ふつうの定石だけで解けます」「仮定が 2 回要ります」
「2 段の読みが 1 回要ります」など）、仮定なしで盤の何割まで進めるか、仮定が要る場面（盤のどこまで進んだところで、
何段・何手の読みか）、使う読みの定石、よく使う定石を添えます。

盤面の総当たりソルバ（`countSolutions`）は検証専用で、出題には使いません。
テストでは、生成した問題が「解き味がちょうど宣言した難易度」「その深さの推論だけで解ける」「解が一意」「正解が単一ループ」であることを毎回確かめています（`npm run verify` は大量に作って同じことを確かめます）。

### 証明だけで解き切れるかの確認

ソルバの「解けた」は、背理法の候補をどの順で試すかに左右されます。実際、空の盤面からは
解けるのに、途中まで進めた盤面からはソルバが先へ進めず、ヒントが「もう決まる場所はない」と
止まってしまう問題がありました。

そこで作問の最後に、ソルバとは別の方法でもう一度確かめます（`solveWithProofs`）。

1. 空の盤面から、**検算に通る証明が付いた手だけ** を置いていく
2. 証明は、盤面だけで決まる手 → 仮定 1 つで矛盾 → 仮定を重ねて矛盾、の浅い順に探す
   （仮定の深さは難易度の上限まで。やさしいは仮定なし）
3. 正解まで届かなければ、その問題は捨てて作り直す

ヒントはこれと同じ証明探しを使うので、配信される問題は **どこまで進めても、正しく置いている
かぎりヒントが根拠つきで次の一手を示せる** ことになります。正しい値を否定する証明は作れない
ので、証明だけで全部の辺が決まれば解は自動的に一意です。

問題コードの読み込みも同じ確認を通ったものだけを受け付けます。
`npm run verify` は正解を使わずに（両方の値を仮定して）この確認も行います。

## 問題コード

`10h31QNRALSBQ0DICOYQUOWiZWdxGOU` のような短い文字列で 1 問を表します（URL に載せるので短くしています）。

- `<縦><難易度><本体>`（正方形）か `<縦>x<横><難易度><本体>`（例 `6x8n…`）
- 難易度は 1 文字：入門 `b`・やさしい `e`・ふつう `n`・むずかしい `h`・鬼 `x`
- 本体は、マスごとに「数字があるか」1 ビット＋あれば数字（0〜3）2 ビットを並べ、6 ビットずつ URL にそのまま使える
  文字（`A-Z a-z 0-9 - _`）にしたもの。数字が 4 割の盤なら 1 マスあたり約 1.8 ビットで、10 × 10 で 30 文字ほどです

以前の形式（`7x7:n:23123a0d1d…`。数字をそのまま、空白マスの連続を `a`〜`z` で表したもの）も読み込めます。
その場合も、開いたあとは短い形式に直します。

いまの問題はいつも URL（`?p=<コード>`）に出ています。新しい問題になるたびに書き換えるので、アドレスバーの URL を
そのまま送れば同じ問題を開けます（履歴は増やさないので、戻るボタンで前の問題には戻りません）。
URL の問題が途中まで解いて保存してある問題と同じなら、再読み込みしても続きから遊べます。
メニューの「問題コード」からもコピー・読み込みができます。
